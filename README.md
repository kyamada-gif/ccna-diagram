# 計算なしの図表問題

CCNA の「束B」（出力・図・画面を読む問題）のアプリ。
`ipcalc2/` と同じ作り方（React ＋ `app.jsx` → `build.js` → `app.js`）。

## いちばん大事な決まり（2026-08-20 オーナー）

> **テストは、問題集PDFに載っている問題そのものを出す。全分野で。**
> **練習は、そのテストを解けるようになるためのもの。**

これ以上でも以下でもない。ここから外れる作り方をしない。

| | テスト | 練習 |
|---|---|---|
| 中身 | **本の問題そのまま** | **その場で作る（生成問題）** |
| 1問の単位 | **本の1問＝画面の1問。分けない** | 見る所ごとに小さく割る |
| 絵（図・機器の画面） | **紙面から切り出した画像** | 作った出力・作った図 |
| 文字の出力（show出力・JSON・設定） | 紙面と一字一致の写し | その場で作る |
| 置き場所 | `q/<ブロック>.js` | 置き場所は無い。`types/<ブロック>.js` が毎回作る |

**練習に本の問題を出さない。**21ブロックすべてが生成問題になっている。
`node build.js` が毎回、練習の1問1問を本の問題と突き合わせて確かめる
（問題文が同じ／提示物が同じ／出どころの番号が付いている、のどれかがあれば止まる）。

### 練習の形（全ブロック共通）

```
覚える1枚（learn）  … その見る所は何か・どう使うか
      ↓
その所の問題2問（step）… その所だけで決まる問題を、その場で作る
      ↓ （見る所の数だけくり返す）
最後に3問（whole）  … 提示物ぜんぶで判定／覚えた組み合わせで結ぶ
```

ブロックの作りは2種類。**画面はこの2つを見分けない。**

| 作り | 中身 | ブロック |
|---|---|---|
| `kind:"rules"` | 見る所を上から順に見て、規則で答えを出す | 14ブロック。`types/<id>.js` に書く |
| `kind:"match"` | 言葉と説明の対を覚える | 7ブロック。**書くファイルは要らない。**過去問の対から `engine.js` の `makeMatchEngine` が組み立てる |

`build.js` が毎回、この決まりを機械で確かめる（下の「見張り」）。

```
showread/
  index.html      画面の地。文字7段・余白6きざみは ipcalc2 と同じ
  engine.js       共通の仕掛け。makeEngine（規則）と makeMatchEngine（対で覚える）
  gen.js          engine と types を組み立てるところ
  types/<id>.js   ブロックごとの見る所・判定ルール・出力の作り方（14ブロックぶん）
  questions.js    問題の入れ物。中身は q/ に置く
  q/<id>.js       **テスト用の過去問。**本の1問＝1件
  q/synonym.js    言い換え表。**練習だけ**で使う（テストは本の言葉のまま）
  img/<qid>.png   紙面から切り出した提示物
  img/index.js    qid → 画像の表。**画面はこれを引く**（問題データに画像を書かない）
  app.jsx         画面。ここは直す。判定も問題作りもしない
  app.js          自動生成。手で直さない
  build.js        app.jsx → app.js ＋ 検査
  vendor/         React（ipcalc2 からコピー）
```

## 画面の言葉の決まり

### 画面は2つだけ

```
ホーム（分野が21行）
  └ 行を押すとその場で開き、[練習をする][テストを受ける]
       └ 練習 or テスト（1画面1問）
            └ 結果
```

**「分野を選ぶ画面」は作らない。**ホームの行がそのまま入口になる。
練習もテストも、**ホームから2タップで1問目**が出る。

行を開くのは1つだけ（もう一度押すと閉じる）。
21行ぶんのボタンを最初から全部出すと、どこを見ればいいのか分からなくなる。

4つの札（1〜4）は、**押せない小見出し**として行のかたまりを区切るだけ。

### 名前の付け方（`app.jsx` の上のほうに1か所でまとめてある）

| もの | 書き方 | 例 |
|---|---|---|
| 札 | 番号＋名前 | `1 出力を読んで当てる` |
| 分野 | 札.分野＋名前 | `1.1 show interface の障害` |
| やり方 | 「練習」「テスト」 | **テストは分野に1本。回の番号は無い** |

### 印（バッジ）の決まり

3つの状態しかない。**どの画面でも同じ見た目**（`Mark` の1か所）。

| 状態 | 見た目 | いつ |
|---|---|---|
| まだ | 破線の空の枠 | 一度も受けていない |
| 途中 | 枠の下に最高点「28 / 31」 | 受けたが、まだ届いていない |
| 届いた | 🏅 | 届いた |

**数えるものは分野のバッジ1種類だけ。**分野は21ある。
ホームの上に「🏅 n / 21 分野」と出す。札にバッジは付けない。

前は「回ごと（38個）→ 分野（21個）→ 札（4個）」の3段だった。
数え方が3つあると、何を集めているのか分からなくなる。

### バッジが付く線は9割

`passLine(len) = Math.ceil(len * 0.9)`。**例外を作らない。**

| 本の問題 | 正解が必要な数 |
|---|---|
| 31問 | 28問 |
| 31問 | 28問 |
| 10問 | 9問 |
| 9問以下 | 満点（オーナーの判断でそのまま） |

### 画面の言葉は、講義でそのまま使える日本語にする

**分かりやすくするつもりで、ふだん使わない言い方に置きかえない。**
オーナーとの会話で使うのと同じ、普通の日本語で書く。説明的でよい。

| 書かない | 書く | なぜ |
|---|---|---|
| くらべる・こわれる・しくじる | 比べる・壊れる・失敗する | 常用漢字をひらがなにしない |
| 住所 | IP アドレス | 自分で作った言いかえは、かえって分かりにくい |
| 合言葉 | 事前共有キー | 同上 |
| 載せる先 | 所属させるインターフェース | 同上 |
| 代表になりたい度合い | 代表に選ばれやすさを決める設定値 | 機器は「なりたい」と思わない |
| 〜を打つ | 〜を入力する | 話し言葉に寄せない |
| 〜の話 | 〜について | 同上 |
| 最も大きい数 | 優先度の値が最も大きいルータ | **何の数かを必ず書く** |
| `コマンド` | コマンド | バッククォートは画面にそのまま文字として出る |

`node build.js` が `spots` `rules` `gloss` `name` `note` `ask` を見て、
左の列の言い方が残っていたら止める。

### 書きかけの印を残さない

覚え書き（コメント）では `**ここが大事**` と書いてよいが、
**画面に出る文字列に書くと、記号ごと表示される。**
`node build.js` が `spots` `rules` `gloss` `name` `note` `ask` と
`app.jsx` の画面の文を見て、`**` が残っていたら止める。

### 先へ進むボタンの置き場所

**本文のすぐ下に置く**（`.dock` は `position: sticky; bottom: 0`）。
本文が短いときは内容のすぐ下に、長いときは画面の下に貼りつく。
前は画面の下の段に固定していたが、本文が短いと
「ぽつんと下に離れたボタン」になって分かりにくかった。

### 説明の1枚は、短く（`spec.brief`）

**文字は読まれない。**見たらすぐ「こう来たら、こう答える」と分かる形だけを残す。

```
   1  [
   2    {"switch": "SW18", "port": "ge2/41"},   ← 見本。決め手の所だけ光らせる
   3  ]

        コロン : の 左        ← 見る所（記号そのもの）
             ▼
            キー             ← そのときの答え（大きく・緑）
         英語では key         ← 本の別の書き方だけ、小さく
```

分野が `spec.brief(block, i)` を持っていれば、この短い形になる。
返すのは `[{ if, then, note }]`。`then` は配列にすると、同じ箱の中に縦に並ぶ。

持っていない分野は、いままでの形（何を表すか／どう使うか／ここで決まるとき）のまま。

JSON では 108字 → 20字ほどになった。

### 答え合わせの言葉も、同じ書き方にそろえる（`spec.note`）

**同じことを2回書かない。**判定ルールの文と、答えの一言説明が
どちらも「開くかっこを上から数える」になっていて、2行とも同じ意味だった。

分野が `spec.note(v)` を持っていれば、**決まりと、この場合の数字を別々の行**に出す。

```
        2                        ← 答え
   [ の数 ＝ 配列                ← 決まり（説明の1枚と同じ書き方）
   [ は 2 個                     ← この場合の数字
```

返すのは `{ gloss, body }`。持っていない分野は、いままでどおり
判定ルールの文（`why`）と答えの一言説明（`gloss`）をそのまま出す。

### 終わったあとの画面（結果）

練習もテストも、終わりの画面は同じ形。**上に点数、下に「次にやること」**。

| | 上に出るもの | 下のボタン（左が緑＝本筋） |

### 間違えた確認項目だけを、もう一度

練習の記録には、1問ごとに `spotNo`（何番目の確認項目か）が入っている。
最初の答えが外れた確認項目を集め、**その番号だけで練習を組み直す**（`makeReview()`）。

- 問題はその場で作り直すので、**同じ問題は出ない**。
- 引くのは番号であって、名前ではない。
  確認項目の名前（`look` をつないだ文）は、別の項目と同じ文になることがある。
  名前で引くと、別の項目にすり替わる。

**key に分野とやり方の両方を入れる。**入れないと、
練習からテストへ移っても前の問題と点数がそのまま残る。

### 画面の行き方

```
ホーム（分野が21行。4つの札は押せない小見出し）
  └ 行を押すと、その行の中が開く
        └ [ 練習をする ]      [ テストを受ける ]
                ↓                    ↓
           練習（生成問題）      テスト（本の問題ぜんぶ）
                ↓                    ↓
              結果 ──「この分野のテストを受ける」──┘
```

**練習は緑、テストは灰の枠。**緑は「いま進む道」1つだけ。

「分野を選ぶ画面」は無い。ホームの行がそのまま入口。

### 動くのはページそのもの（中に別のスクロールを作らない）

**これは決まりごとで、外すと拡大したときに壊れる。**

前は「画面の高さに固定した箱の中だけが動く」形にしていた
（`body{overflow:hidden}` ＋ `#root{height:100dvh}` ＋ `.wrap{overflow-y:auto}`）。
この形だと、**画面を拡大したときに本文のいちばん上まで戻れなくなる。**
拡大すると見えている範囲は小さくなるのに、箱は画面の高さのままなので、
中身がはみ出さず、動かす先が無くなるため。

いまはふつうのページと同じで、ページ全体が動く。

| もの | 決まり |
|---|---|
| `html` `body` | 高さも `overflow` も指定しない |
| `#root` | `min-height:100dvh` だけ（`height` にしない・`overflow:hidden` にしない） |
| `.wrap` | 中でスクロールさせない（`overflow-y` を付けない） |
| `.dock` | `position:sticky; bottom:0` |
| 見ている位置 | `document.scrollingElement.scrollTop`（`app.jsx` の `nowY` `toTop`） |

`.dock` は sticky なので、本文が長いときは画面の下に貼りつき、
短いときは本文のすぐ下に置かれる。

**`position:fixed` は使わない。**fixed は「目に見えている範囲」ではなく、
ブラウザが内部で持っている枠に貼り付く決まりになっている。
スマホのアドレスバーの出入りや、画面を拡大したときに枠と見える範囲がずれると、
ボタンが下にはみ出して**スクロールしないと出てこない**状態になる。

### テスト（分野に1本。過去問をぜんぶ通る）

「テストを受ける」を押すと、**すぐ1問目**が出る。選ぶ画面は無い。

- その分野の過去問**ぜんぶ**が1回のテストになる（2問〜31問）
- 並びは **qid 順で固定**。出る順番だけ毎回混ぜる
- **9割できたら、その分野に 🏅**
- テスト中に「もどる」を押すとホームに戻る

前は10問ずつの「回」に分け、回ごとにバッジを付けていた。
バッジの数え方が3段になって、何を集めているのか分からなくなったのでやめた。

### 間違えたとき（lpic-reflex と同じ）

| | 練習 | テスト |
|---|---|---|
| 正解に ✓、押したものに ✕、残りは薄く | ○ | ○ |
| 答え合わせ（見た所と数字、消える理由）を出す | ○ | ○ |
| **「次へ」を出さず「🔁 もう一度チャレンジ」だけ** | ○ | — |
| 「次へ」で進む | — | ○ |

**点になるのは最初の答え。**やり直しても点は増えない。

キーボードは **A〜D / 1〜4 で選ぶ、Enter で次へ・やり直し**。

## 左と右を結ぶ問題（対応づけ）

本では「左の説明を、右の箱にドラッグして入れる」形。**本の1問のまま出す。**

- 操作は1種類。**説明を押す → 入れ先を押す。**もう一度説明を押すと外れる
- 引っぱって落とす形にしない（小さい画面で押し間違えるため）
- **全部の組が合って、初めて正解**（本の1問＝1点）。部分点は付けない
- 答え合わせでは、合った組に ✓、違った組に ✕ と正しい入れ先を出す
- 練習でやり直すときは、**合っている組だけ残して、違う組を外す**

形は2つあるが、操作は同じ。

| 形 | 中身 | 数 |
|---|---|---|
| 振り分け型 | 4〜6個の説明を、2つのグループに振り分ける | 多い |
| 1対1型 | 4〜6個の説明を、4〜6個の言葉に1つずつ結ぶ | 次に多い |

データの形（`q/<ブロック>.js`）。

```jsonc
{ "qid":"B1-P11-002", "from":["B1-P11-002"], "book":"B1",
  "text":"ワイヤレスの対応づけ（ドラッグアンドドロップ）",
  "kind":"match",
  "pairs":[{"l":"CAPWAPトンネリングプロトコルを使用します","r":"スプリットMAC"}, …],
  "targets":["スプリットMAC","自律型"],
  "explanation":"" }
```

**練習では、この1問を「1組＝1問の4択」に開いたものを出す**（`q/practice/`）。
開いたものは `scripts/matching.py`（`--pairs` を付けない側）が作る。

## 提示物の出し方

**画像と文字は、両方出せる。**

1. 紙面の切り出しがあれば、まず画像（`img/index.js` を qid で引く）
2. `covers` が `fig` なら、書き起こしの**図の段だけ**を画像に譲り、
   文字の段（show出力・設定・機器の画面）はその下に出す
3. `covers` が `all` なら、書き起こしは出さない（図と出力が同じ箱に入っている）

書き起こしは `【ネットワーク図】` `【SW1 の show interface】` のような見出しで区切ってある。
見出しが無くても、**空行のあとに機器の合図（`R1#` など）や設定の言葉が来たら、そこから下は文字**として扱う。
「画面」の見出しは文字のまま残す（機器の画面は別の箱に刷られていて、図の切り出しに入らないことがあるため）。

## 分類を増やすとき

1. `gen.js` に、その分類の `SPOTS`（見る所）と `RULES`（判定ルール）を足す
2. `questions.js` を、その分類の過去問に差し替える
3. `app.jsx` の `TYPES` で `ready: true` にする

いまの `gen.js` は「show interface の読み取り」1分類ぶん。
分類が増えたら、分類ごとに持てる形に分ける。

## 1問の形（練習もテストも同じ）

**画面側は kind で場合分けしない。**あるものを出すだけ。

```jsonc
{ "kind": "past",        // learn 覚える1枚 / step 見る所ごと / whole ぜんぶ見て / past 過去問
  "ask": "どのスイッチがルートブリッジに選ばれますか。",
  "exhibit": { "kind": "topology", "fig": {…} },   // または {"kind":"console","text":"…"}
  "image": { "src": "img/B1-P15-025.png", "w": 410, "h": 356 },  // 紙面の実物。無ければ null
  "opts": ["SW1","SW2","SW3","SW4"],
  "right": ["SW3"],      // **いつも配列**（答えが2つ以上の問題があるため）
  "extra": { "maclist": true },   // その形だけが持つもの
  "note": { "qid":"B1-P15-025", "book":"B1", "explanation":"…" }  // 過去問だけ
}
```

- **練習** … その場で作る。同じ問題は二度と出ない（200回作って200通り）
- **テスト** … 過去問そのもの。全問が必ずどれかの回に入る
- 紙面の実物（`image`）があればそれを出す。無ければ `exhibit` から描く

## 学習の記録（store.js）

**いまは localStorage だが、サーバのDBのつもりで扱う。**
載せ替えるときに直すのは `store.js` の `load` / `save` / `add` だけ。

**練習もテストも、同じ1つの形（attempt）でためる。**1回の演習＝1件。追記だけで、書き換えない。

```jsonc
{ "id": "a-mt1c5h3l-0l4d",        // 一意。二重に入れないための番号
  "app": "showread",
  "version": "showint:31,rootbridge:23",   // 問題データの版
  "user": null,                    // いまは無し。サーバでは必須
  "block": "rootbridge",
  "mode": "test",                  // "practice" / "test"
  "set": "B1-P12-034..B2-0095-02#10",      // 出題範囲。**番号ではなく中身で決める**
  "startedAt": "…", "endedAt": "…", "seconds": 208,
  "asked": 10, "score": 9, "of": 10, "passLine": 9, "passed": true,
  "answers": [
    { "no": 1, "kind": "past",     // learn は問題ではないので入れない
      "qid": "B1-P15-026",         // 過去問だけ。作った問題は null
      "spot": null,                // 練習のとき、どの確認項目か（画面に出す名前）
      "spotNo": null,              // その確認項目の番号。名前は重なることがあるので、
                                   // 「間違えた所だけもう一度」はこの番号で引く
      "firstOk": true,             // **点になるのは最初の答え**
      "tries": 1,
      "picked": ["SW2"], "right": ["SW2"], "ms": 12000 } ] }
```

### set を「番号」にしない理由

前は `tests["0"]` のように**位置**で持っていた。`"0"` は「qid順で先頭10問」という意味しかなく、
**過去問を1問足すと区切りがずれて、同じ `"0"` が別の問題の集まりを指す。**
いまはテストが分野に1本なので `rounds` の中身も1つだけだが、
**名前を中身から作る決まりは変えない**（問題を足せば名前も変わり、古い記録と混ざらない）。
過去の記録が静かに嘘になるので、中身から決まる名前（先頭の qid 〜 末尾の qid ＋ 問数）にした。

### 画面が使う「いまの状態」

ためた記録から毎回作り直す（`summarize`）。**ためない。**

```jsonc
{ "blocks": { "rootbridge": {
    "practiced": true,
    "rounds": { "B1-P12-034..B2-0095-02#23": {"best":21,"of":23,"passed":true,"at":"…"} },
    "badge": false } } }
```

- **触っていないブロックもキーを作る。**無いと、受け取る側が毎回「無いのか 0 なのか」を考える
- **まだやっていない分野の点は `null`。`0` にしない**（「0点」と区別が付かなくなる）

## JSON の分野に入っている問題の種類

過去問41問は、聞かれ方で5つに分かれる。**この5つが練習の確認項目にそのまま対応する。**

| 聞かれ方 | 問数 | 何を答えるか | 確認項目 |
|---|---|---|---|
| その言葉が何を表すか | 20 | キー／値／配列 | コロン ( : )／角かっこ [ ] |
| その行が何を表すか | 8 | オブジェクト／配列 | 中かっこ { }／角かっこ [ ]／行の番号 |
| いくつあるか | 4 | 数 | かっこの組の数 |
| 全体が何型か | 4 | オブジェクト／配列 | 中かっこ { }／角かっこ [ ] |
| **何が足りないか** | **3** | 足りない閉じかっこ | **かっこの閉じ忘れ** |
| まとめて数える | 1 | 「1つのオブジェクト、3つのキー…」 | かっこの組の数 |

聞かれ方は `q/json.js` の `exhibit.asked.mode` に入っている
（`scripts/json_block.py` が本の問題文から起こす）。
**同じ JSON でも聞かれ方が違えば答えが違う**ので、これが無いと判定できない。

### 「何が足りないか」の3問

もとは「そのほか」の分野に入っていた（2026-08-21 に移した）。
`bucket_review.csv` で目標6.5（REST API の特性）に分類されていたため、
目標6.7 で拾う `json_block.py` から漏れていた。中身は JSON の書き方そのもの。

- **本は同じ答えを3冊で違う書き方で刷っている。**
  「末尾に中括弧（}）」「末尾の中括弧（ } ）」「末尾の中括弧 ( } )」。
  共通するのは「中括弧」の3文字だけなので、`same` はそこで当てる

  （生成した JSON では `]` が足りないこともある）

## 出題パターンで絞る（テストを短くする）

**同じ聞かれ方の問題が何問も並んでいると、テストが長いだけで身に付かない。**
JSON は41問のうち「単語 → 値」が7問、「単語 → キー」が6問あった。

そこで2段階で絞る。**絞り方は分野ごとの生成スクリプトに書く。**

1. **本が違うだけの同じ問題を1つにまとめる**（提示物・聞かれ方・答えが同じもの）。
   残したほうの `from` に、まとめた問題番号を全部入れる
2. **同じ出題パターンは上限まで**（いまは3問）。あふれた分は外す

外した問題は `out/full/not_used.csv` に理由つきで載せる。
**`from` にぶら下がっている別の本の問題も、一緒に載せる**（載せ忘れると全問カバーの見張りに引っかかる）。

### 出題パターンが消えていないか、毎回確かめる

絞ったせいでパターンが1つでも消えたら、その聞かれ方はテストに出なくなる。
分野が次の2つを持っていれば、`node build.js` が毎回確かめる。

| 名前 | 中身 |
|---|---|
| `spec.patterns` | 本にあった出題パターンの一覧（**絞る前に数えたもの**） |
| `spec.pattern(q)` | 過去問1問 → そのパターンの名前 |

パターンが消えていても、見覚えのないパターンが増えていても止まる。

### 絞り方は `scripts/trim.js`（どの分野でも使える）

```bash
node scripts/trim.js showint 2           # 何が起きるか見るだけ
node scripts/trim.js showint 2 --write   # q/showint.js を書きかえる
```

**外す問題の一覧は、書きかえる前に取っておくこと。**
書きかえた後に走らせても、もう外すものが無いので空になる。

```bash
node scripts/trim.js showint 2 | grep '^B' > /tmp/drop.csv   # 先に取る
node scripts/trim.js showint 2 --write
cat /tmp/drop.csv >> ../out/full/not_used.csv
```

## 誤答が足りないとき（本の誤答を借りる）

決め方が1つしかない分野（ログの読み取り）は、答えの顔ぶれも1つになる。
そのままだと選ぶものが1個しか出ず、問題として成り立たない。

**そこで、同じ分野の本の問題が出している「正解でない選択肢」を借りる**
（`engine.js` の `spareWrongs()` / `padOpts()`）。

- **こちらで誤答を考え出さない。**借りるのは本の言葉だけ
- その分野で正解になっている文と、`same` に載っている言い換えは、誤答にしない
- 本によって「〜する」と「〜します。」が混じっているので、
  **句点で終わらない言い方を先に使う。**混ぜると、言い回しの違いだけで正解が当てられてしまう
- 借りるのは選択肢の文だけ。問題文と提示物は借りない
  （練習に本の問題そのものを出さない、という決まりは崩れない）

`node selftest.js` が、**こちらで作る問題の選択肢が3つ以上あるか**を毎回見張る。
本の問題（`kind:"past"`）は数えない。**本が2択で出しているものは、そのまま出す。**

## 規則で出せない問題の扱い（bookOnly）

判定ルールでは答えが出せないが、**問題としては出せる**ものがある。
例：`{"apple": ["red", 1]}` で「apple は何を表しますか」。選択肢が
配列／オブジェクト／番号／文字列 で、「キー」が無い（本は文字列を答えにしている）。

こういう問題は `spec.bookOnly = ["B2-0031-03", …]` に入れる。

- **判定の検査からだけ外す。問題はテストに出る**（取りこぼしを作らない）
- 答え合わせは、本の解説だけが出る（見た所と数字は出ない）
- `spec.dropped`（本の答えが矛盾していて使えない）とは別物。混ぜない

## 決まり

1. **判定と出力作りは `gen.js`。**画面側（`app.jsx`）では判定しない
2. **過去問は `questions.js`。**画面側に問題を書かない
3. **正解するまで次へ進まない**
4. **画面の言葉は説明だけ。**励ましも呼びかけも書かない
5. 文字は7段・余白は6きざみ（`index.html` の `:root`）。ipcalc2 と同じ
6. **判定ルールは過去問と解説から起こす。**思いつきで足さない
